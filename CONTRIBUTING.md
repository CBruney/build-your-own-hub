# Making this your own

Start by copying the kit into your own project. Write your choices in a profile and personal brief; keep personal information out of changes you send back to others.

For a reusable improvement, describe the concrete problem, the changed behavior, and the verification performed. Use fictional fixtures. Add a test when it protects a meaningful contract, particularly source timestamps, partial reads, hidden state, unsafe links, or duplicate actions. Screenshots should use the original fictional snapshot.

Run `npm test`, `npm run build`, and `npm run verify`. Check relevant browser interactions and mobile layout. Update the guide if a user-facing capability or limitation changes. Keep the font attribution if the assets remain.

Do not add secrets, private source exports, service tokens, browser profiles, local machine paths, or personal screenshots. The original kit has no installed automation and no account connection. Keep new external actions opt-in and independently verified.
